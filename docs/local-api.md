The API runs natively on the Bindicator host under the unprivileged
`bindicator` account. It listens **only** on
`http://127.0.0.1:18050` and does not expose the server to the LAN or
internet. There is no Docker container or subscription. The optional Alexa
skill reaches this API only through the separately configured Cloudflare
Access-protected HTTPS tunnel; the API does **not** listen publicly.

All endpoints other than the minimal health probe require a bearer token
generated by `deploy/install.sh` at `/etc/bindicator/api.token`.
The token is generated once, retained on upgrades, and is readable only
by root and trusted members of the `bindicator` group. Treat it as a secret.

## Build, test and deploy

```bash
cd ~/code/bindicator
git status --short --branch
# Standard released upgrade: switch to main and fast-forward it.
# For an unmerged feature branch (e.g. Echo Show PR #24), remain on that
# branch and use 'git pull --ff-only' instead of switching to main.
git switch main
git pull --ff-only origin main

# Test locally without changing the system installation or Hue lights.
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[test]'
.venv/bin/python -m pytest -q

# Copy the tested application to /opt/bindicator and install the API unit.
sudo bash deploy/install.sh

# The installer enables and starts the API service.
systemctl is-enabled bindicator-api.service
systemctl status bindicator-api.service --no-pager
```

The installer enables and starts the API, the minute-by-minute reminder
timer and the daily calendar-refresh due-check timer. All run as the
restricted `bindicator` service user. See the
[main installation guide](../README.md#install-and-upgrade).

## Test read-only endpoints

```bash
# Unauthenticated health probe.
curl -fsS http://127.0.0.1:18050/api/v1/health | python3 -m json.tool

# Run from a shell logged in as a trusted bindicator group member.
id -nG                 # Should include bindicator
read -r BINDICATOR_API_TOKEN < /etc/bindicator/api.token

# Authenticated status.
curl -fsS \
  -H "Authorization: Bearer $BINDICATOR_API_TOKEN" \
  http://127.0.0.1:18050/api/v1/status | python3 -m json.tool

# Next collection's date, types and colours from the selected provider.
# Uses verified per-provider cache and refreshes the source when due.
curl -fsS \
  -H "Authorization: Bearer $BINDICATOR_API_TOKEN" \
  http://127.0.0.1:18050/api/v1/collections/next | python3 -m json.tool
```

An unauthenticated request to `/api/v1/status` must return **HTTP 401**.
The API never returns private iCalendar feed URLs, property UPRNs or Hue Bridge keys.

## Test control operations only when ready

The commands below **change Bindicator's live state** (and may affect Hue
lights); run them after verifying read-only operations. Every POST requires
`Content-Type: application/json`, the bearer token and a JSON object.

```bash
# Pause and immediately restore an active Bindicator alert where unchanged.
curl -fsS -X POST http://127.0.0.1:18050/api/v1/pause \
  -H "Authorization: Bearer $BINDICATOR_API_TOKEN" \
  -H "Content-Type: application/json" -d '{}' | python3 -m json.tool

# Resume regular reminders.
curl -fsS -X POST http://127.0.0.1:18050/api/v1/resume \
  -H "Authorization: Bearer $BINDICATOR_API_TOKEN" \
  -H "Content-Type: application/json" -d '{}' | python3 -m json.tool

# Toggle paused/active.
curl -fsS -X POST http://127.0.0.1:18050/api/v1/toggle \
  -H "Authorization: Bearer $BINDICATOR_API_TOKEN" \
  -H "Content-Type: application/json" -d '{}' | python3 -m json.tool

# Start a short, detached next-collection preview; restore after 10 seconds.
# Requires Bindicator to be active and have no already-active reminder.
curl -fsS -X POST http://127.0.0.1:18050/api/v1/alerts/next \
  -H "Authorization: Bearer $BINDICATOR_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"seconds":10}' | python3 -m json.tool

# WARNING: without seconds, the reminder remains until its collection
# morning (09:00), unless paused or manually overridden.
curl -fsS -X POST http://127.0.0.1:18050/api/v1/alerts/next \
  -H "Authorization: Bearer $BINDICATOR_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{}' | python3 -m json.tool
```

The API invokes the existing CLI with fixed arguments and no shell,
so locking, pause protection, lamp snapshots and restoration behaviour are
the same. A timed preview starts a separate worker, and the API returns as
soon as it has been launched; the response does **not** mean that the lamp
has already been restored.

To acknowledge the current active collection reminder only (this **changes
live state**), use:

```bash
curl -fsS -X POST http://127.0.0.1:18050/api/v1/bins-out \
  -H "Authorization: Bearer $BINDICATOR_API_TOKEN" \
  -H "Content-Type: application/json" -d '{}' | python3 -m json.tool
```

If there is no active reminder, this returns `acknowledged: false` rather
than acknowledging a future collection. The status field `acknowledged_date`
may remain populated after light restoration, for suppression of that date.

Remove the token from your shell when finished:

```bash
unset BINDICATOR_API_TOKEN
```

## Routes

| HTTP method | Route | Description |
| --- | --- | --- |
| GET | `/api/v1/health` | Minimal, unauthenticated health check |
| GET | `/api/v1/status` | Pause state, active collection, `acknowledged_date`, and tracked indicators |
| GET | `/api/v1/collections/next` | Next collection date, types and colours |
| POST | `/api/v1/pause` | Pause and restore unmodified lights |
| POST | `/api/v1/resume` | Resume reminders |
| POST | `/api/v1/toggle` | Toggle the pause state |
| POST | `/api/v1/alerts/next` | Persist next collection, or preview for `seconds` (1–60) |
| POST | `/api/v1/bins-out` | Acknowledge an active reminder, safely restore unchanged Hue states, suppress only that collection |

Only `POST /api/v1/alerts/next` accepts a nonempty object, with optional
`seconds`. All other POST endpoints, including `/api/v1/bins-out`, require `{}`. The bins-out acknowledgement is
idempotent when no reminder is active and does not change the pause flag.
With an active reminder it saves the acknowledged collection date, restores
lights using the existing manual-override safeguards, and prevents the timer
reapplying that collection. Failed restores retain their snapshots for retry. No generic shell
execution, file-system access, token management, configuration changes,
CORS, or external network binding is provided by this API.

## Diagnostics and shutdown

```bash
systemctl status bindicator-api.service --no-pager -l
journalctl -u bindicator-api.service -n 50 --no-pager
ss -ltn | grep ':18050'
tail -n 30 /var/lib/bindicator/preview.log

# Shut down the optional local API without affecting scheduled reminders.
sudo systemctl stop bindicator-api.service
```

When testing from another computer, mobile device or Alexa skill,
`127.0.0.1` means that **other device**, not the Bindicator host. The optional
[Cloudflare Tunnel and Access integration](cloudflare-setup.md) provides a
separately authenticated HTTPS route for a private Alexa Lambda. Do not bind
this API to `0.0.0.0`, forward port 18050, or place the API token inside
an Alexa client-side interaction model.

See also the [documentation index](README.md),
[LAN management](lan-management.md) and [Alexa guide](../alexa/README.md).
